# ADIA — Audit Recovery Dashboard (Version 1)

Simple SQL-powered Streamlit app. **No AI model yet:** financial figures are computed by SQL, not generated by an LLM. No confidential data is included.

## Run locally (macOS / Linux)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python seed_demo.py
python -m pytest -q
streamlit run app.py
```

Windows PowerShell: activate with `.venv\\Scripts\\Activate.ps1`.

Expected dashboard: `Nu. 80,000.00`, based on three fictional posted payments. The fourth payment is pending and the fifth void.

## Project files
- `app.py`: UI
- `recovery.py`: data access and recovery aggregation
- `seed_demo.py`: fictional SQLite dataset generator (DELETES and recreates *only the demo table in the selected local demo database*)
- `config.py`: configuration
- `tests/`: unit tests
- `SPEC.md`: scope, assumptions, safety
- `FINAL_MASTER_PROMPT.md`: development prompt for future versions

## Real SQL integration (not configured by default)

1. Confirm exact SQL engine, approved schema/views and accounting definition of *recovered*.
2. Obtain a separate reporting user with SELECT permission **only**, limited to approved data and authorized scope.
3. Map the real database columns to the demo query in `recovery.py` (or preferably expose an approved standardized view).
4. Set `ADIA_DATABASE_URL` in the process environment; for non-SQLite engines install the appropriate SQLAlchemy database driver.
5. Validate totals independently against an official report. Never run `seed_demo.py` with real data or production credentials.
6. Add app authentication and per-user authorization before allowing production access.

Receipt paths are intentionally **not opened** in Version 1. Future file processing must validate storage roots/hosts, enforce document permissions, scan uploaded files, and keep originals unchanged.
